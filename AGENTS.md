# ZEAL-Dry coding standard

- Write code for a human maintainer: use descriptive names and straightforward control flow.
- Give every module, class and function a concise explanation of its responsibility.
- Annotate distinct sections when their purpose or safety ordering is not obvious.
- Explain why a protection or calculation exists; avoid comments that merely repeat a statement.
- Remove unused code and consolidate repeated logic when doing so makes the result clearer.
- Add no speculative features, dependencies or abstractions outside the agreed block.
- Keep readability changes behavior-preserving and rerun the existing tests.
